# cyber-egg

免费 Token 探测器 —— 各家 AI 厂商免费额度 / 福利政策的每日采集与展示。

**双屏结构**：`lucky egg`（福利展示，给人看）+ `rsource`（库区，给配置看）。

> 当前覆盖 **124 家厂商 · 40 条福利**，其中 26 条人工核实官方来源、14 条从政策变化流自动提取。

---

## 快速开始

```bash
python run.py          # 采集 → 归一 → 入库 → diff → 生成双屏看板
open site/index.html   # 双击也能打开，数据已内联，无需起服务
```

只需要 **Python 3.10+**，不依赖任何第三方库 —— 采集用 `urllib`、存储用 `sqlite3`、模板用字符串替换。

| 命令 | 用途 |
|---|---|
| `python run.py` | 完整跑一遍（约 14 秒） |
| `python run.py --fast` | 跳过 doc/x 人工复核源，只抓结构化 API（约 5 秒） |
| `python run.py --offline` | 不联网，用今日缓存重算（约 1 秒） |
| `python run.py --sync-ranking` | 额外同步免费模型榜排名与厂商缺口清单（每周一） |

### 自动更新

| 方式 | 说明 |
|---|---|
| **GitHub Actions** | `.github/workflows/refresh.yml` 每天 08:30（北京时间）自动采集并部署到 GitHub Pages |
| **Windows 任务计划** | `daily.cmd`，周一自动带 `--sync-ranking` |

`daily.cmd` 会自己找可用的 Python（先试 `py -3`，再试 `python`），不依赖硬编码路径。

## lucky egg · 福利展示

本质是「今天有什么能领」。所有类别共用**同一张卡片骨架**，只在强调色与图标上区分：

```
┌────────────────────────────────┐
│ [⚡ 限时福利] [★第一梯队] [视频]  │  ← 形态 / 圈层 / 模态 / 地区
│                          [剩5d7h]│
│                                 │
│ 500 万  tokens ×2               │  ← 额度（渐变数字，最大视觉权重）
│                                 │
│ Seedance 2.0 / 2.0 fast 各…     │  ← 标题
│ Seedance（字节·火山方舟）· 10-26 │  ← 厂商 · 核验日期
│ Seedance 2.0 与 2.0 fast 两个…   │  ← 详情（3 行截断）
│ ─────────────────────────────── │
│ [官方]              [⤓ 领] [详情] │  ← 来源等级 + 主/次按钮
└────────────────────────────────┘
```

### 两组筛选维度

**形态**（福利长什么样）—— 单选：

| 类别 | 强调色 | 含义 |
|---|---|---|
| 限时福利 `flash` | 珊瑚红 | 有明确截止时间，倒计时实时走秒 |
| 额度重置 `reset` | 蓝 | 订阅制用量重置，**不是** token 赠送 |
| 周期白嫖 `daily` | 青 | 每日 / 每月 / 每 5 小时刷新 |
| 新户赠额 `signup` | 紫 | 注册或首次开通的一次性额度 |
| 折扣降价 `deal` | 蓝 | 价格优惠，不是免费 |

**圈层 · 模态**（福利属于谁、用来干什么）—— 与形态筛选叠加生效：

| 筛选 | 含义 |
|---|---|
| **★ 第一梯队** | 御三家（OpenAI / Anthropic / Google）+ 国内头部（DeepSeek / 通义 / 智谱 / Kimi / 豆包 / MiniMax / 混元 / 文心）+ 其横向产品线（Nano Banana / Seedance / WorkBuddy 双版本） |
| **国内头部** | 第一梯队里的国内那部分，单独可切 |
| **◈ 图像·视频·设计** | 模态属于 image / video / design 的福利，排除纯文本与语音 |
| **图像 / 视频** | 再细分到单一模态 |

设计要点：`圈层` 用金色 chip，`模态` 用紫色 chip，与形态筛选的黑色选中态区分开，避免混成一片。

模态是**先看标题与标签，再看详情**判定的。早期只看全文，导致「硅基流动注册送 14 元代金券」因为详情里提了画图模型就被判成图像类 —— 主福利明明是代金券。现在这类边界情况改为在 `events.json` 里显式写 `modality`。

按圈层或模态筛选时，**「额度重置追踪」区块会自动让位**。它是订阅额度回收，不属于任何图像视频分类，强行保留会一直占着首屏。

### 图像 / 视频 / 设计类福利（已核实）

| 厂商 | 福利 | 来源 |
|---|---|---|
| **Seedance**（字节） | 火山方舟体验中心 2.0 与 2.0 fast 各 500 万免费 token；不支持全能参考，仅首尾帧 | 火山引擎官方公告 |
| **即梦 AI** | 每日约 60 免费积分，10 秒 2.0 fast 约耗 50 积分；豆包 App 每日约 10 次 | 官方 + 第三方交叉核对 |
| **Nano Banana** | AI Studio 免费层 15 RPM / 1500 RPD，折算约每日 500 张图，免绑卡 | Google 官方速率限制文档 |
| **Lovart** | 免费层每月若干完整设计稿，可商用、全分辨率导出 | ⚠️ 官方博客写 10/月、产品页 FAQ 写 50/月、第三方站写 0 —— **三处口径冲突，注册后以账户实际为准**，卡片上已标注存疑 |

### 关于「OpenAI 何时重置」

重置追踪卡记录 `@thsottiaux`（Tibo，OpenAI Codex 负责人）的 **28 天挑战**：每天要么发布一项改进，要么全面重置所有付费用户用量。时间轴逐日标注 Day 3/6/7/8/10 已发生事件，当前进度 21/27。

卡片明确写着 **「下一次重置：官方未公告」+「不做时间预测」**。已发生 4 次里 3 次只隔 1 天，文档标为「历史模式，不构成对未来时间的预测」——这是刻意的克制，预测错比不显示更有害。

### 信息源的诚实边界

卡片分两档来源，界面用颜色区分：**官方**（绿，厂商官网/文档/官方账号，人工核实登记）、**聚合**（琥珀，第三方站自动提取，未逐字核对）。

**为什么不全部自动抓**：实测通义听悟权益页、WorkBuddy 订阅政策、智谱定价页、火山方舟控制台全是 SPA，`urllib` 只能拿到空壳 HTML。硬抓等于制造「看起来有数据其实是空」的假象。所以 `doc` / `x` 类源明确标「人工复核」。

**X 的现状**：本机网络下 X 全端点不可达（SSL handshake 超时 / 代理 502），连 `cdn.syndication.twimg.com`、nitter、RSSHub 都不通。所以 X 源默认不探测（否则每轮白等 2 分钟），Tibo 推文记录为人工核实归档。验证可达性：`python run.py --probe-x`。

## rsource · 库区

| 标签 | 作用 |
|---|---|
| **信息源** | 11 个源的启停、状态、地址、贡献。区分 api / doc / x 三类与「正常 / 人工复核 / 缓存 / 已停用 / 失败」五种状态 |
| **厂商覆盖** | 31 家前沿厂商关注清单（S/A/B 三级）与实际收录比对，S 级缺失标红并显示在顶栏 |
| **排名同步** | 免费模型榜的厂商排名 + 「榜上有名但库里没有」的补全建议 |
| **全部厂商** | 121 家完整库，支持搜索、按分级/名称/核验日期排序 |
| **变化记录** | 字段级 diff（前值 → 后值），自己算的，与上游变化流互相印证 |

**WorkBuddy 双版本**：`WorkBuddy 国内版`（workbuddy_cn）与 `WorkBuddy 国际版 / Buddy AI`（workbuddy_intl）在覆盖页与厂商表里都置顶显示，带 `S` 标记。二者是两套独立体系 —— 国内站点 workbuddy.cn，国际站点 workbuddy.ai，额度政策不同。

它们不在任何上游 JSON 里（上游只覆盖 API 开放平台），靠 `augment_from_events()` 从人工事件库补成 provider 记录，并赋予负 rank 排到列表最前，否则会沉在 121 家末尾等于看不见。

## 快速开始

```bash
python run.py                  # 采集 → 归一 → 入库 → diff → 双屏看板
python run.py --sync-ranking   # 额外同步排名与缺口清单（每周一）
python run.py --fast           # 跳过 doc/x，只抓结构化 API（约 5s）
python run.py --offline        # 不联网，用今日缓存重算
python run.py --probe-x        # 真正探测 X 源（很慢，默认不做）
```

产物：

- `site/index.html` —— 双屏看板，数据内联，**双击即可打开**
- `site/data.json` —— 给其他程序消费
- `data/cyber-egg.db` —— SQLite
- `data/snapshots/YYYY-MM-DD.json` —— 每日快照
- `.cache/raw/YYYY-MM-DD/` —— 上游原始快照

实测耗时：全量 14.3s（5/5 结构化源可用）· `--fast` 约 5s。

## 维护手册

### 加一条福利

编辑 `config/events.json` 的 `events` 数组。**必填** `source`（可点开的官方链接）和 `verified`（核验日期），否则不算数。

```json
{
  "id": "唯一id",
  "vendor": "厂商id（与 providers 表一致，没有会自动补一条）",
  "vendor_name": "展示名",
  "card": "flash | reset | daily | signup | deal",
  "title": "一句话说清送什么",
  "amount_text": "5 亿",
  "amount_unit": "tokens",
  "detail": "细节、限制、坑",
  "how_to": "怎么领",
  "claim_url": "领取入口",
  "source": "官方来源",
  "source_grade": "official | aggregator | manual",
  "ends_at": "2026-10-26T09:00:00+08:00",
  "verified": "2026-10-26"
}
```

`amount_text` 若是「免费」「公测」这类非数字，会自动用小字号渲染，不会撑破卡片。

### 加一个信息源

编辑 `config/sources.json`。`kind` 决定采集策略：`api` 必须返回可解析 JSON；`doc` 只求可达；`x` 默认不探测。

### 加一个必须收录的厂商

编辑 `config/watchlist.json`，`tier: "S"` 表示缺失即标红。`aliases` **第一个应当是承载福利信息的那条记录** —— 例如 WorkBuddy 写成 `["workbuddy_cn", "codebuddy_workbuddy"]`，因为前者才是人工核实的福利记录，后者是上游的编程工具视角。

## 已知边界

- **自动提取有噪声下限**：上游变化流里混着大量「活动已结束」「取消免费额度」「转为收费」。用 `is_benefit_news()` 做负面词过滤（实测从 32 条收敛到 14 条干净条目），但这是启发式规则，不可能 100% 准确。所以自动条目一律标「聚合」。
- **`free_quota` 是散文不是数值**：能展示能搜索，不能直接排序做额度排行榜。
- **跨源合并靠别名表**：`ALIAS_INTEL_TO_PACO` 手工维护 22 组，上游新增厂商需手动补。
- **上游是单人项目**：`free-llm-intel` 靠一个人维护，双源设计就是兜底。
- **静态页的开关不生效**：信息源启停开关只改显示状态，要真正影响采集需改 `config/sources.json`。
